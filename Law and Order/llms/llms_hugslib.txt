### Harmony Patch Types Explained

Source: https://github.com/unlimitedhugs/rimworldhugslib/wiki/Introduction-to-Patching

Explains the different types of patches available in the Harmony library for modifying RimWorld's base game methods. Covers Prefix, Postfix, and Infix patches, their execution order, capabilities, and compatibility considerations.

```APIDOC
Patch Types:

- Prefix:
  - Executes before the original method.
  - Can modify method arguments and cancel original method execution.
  - Can be prevented from executing by other prefixes on the same method.

- Postfix:
  - Executes after the original method.
  - Can modify the return value.
  - Always executes, regardless of prefixes.
  - Preferred for hooking into execution flow without altering behavior.

- Infix (Transpiler):
  - Modifies the method's code instruction by instruction.
  - Advanced topic requiring knowledge of .NET CIL.
  - Neither affects nor is affected by prefixes and postfixes.
```

### Postfix Patch for Property Getters

Source: https://github.com/unlimitedhugs/rimworldhugslib/wiki/Introduction-to-Patching

Illustrates how to patch property getters using `HarmonyPatch` with `PropertyMethod.Getter`. This example modifies the `CanLayNow` property of `CompEggLayer` to make chickens lay eggs 100 times faster. It uses reflection via `AccessTools` to access a private field. The `__result` parameter, when marked with `ref`, allows modification of the property's return value.

```cs
// original property: public bool CanLayNow
[HarmonyPatch(typeof(CompEggLayer))]

public static class EggLayer_CanLayNow_Patch {

	[HarmonyPostfix]
	public static void ExtraFastEggs(CompEggLayer __instance, ref bool __result) {
		__result = (float)eggProgressField.GetValue(__instance) * 100f > 1f;
	}
}
```

### Optional HugsLib Integration for Settings

Source: https://github.com/unlimitedhugs/rimworldhugslib/wiki/Adding-Mod-Settings

Demonstrates how to implement settings that only load if HugsLib is present by catching TypeLoadException. This allows mods to have configurable options without a hard dependency.

```cs
[StaticConstructorOnStartup]
public class TestMod {
	private static Func<bool> getSettingValue;

	static TestMod() {
		// load order does not matter- HugsLib initializes before StaticConstructorOnStartup
		InitializeSetting();
		Log.Message("Setting value: " + getSettingValue());
	}

	private static void InitializeSetting() {
		const bool defaultValue = true;
		// Need a wrapper method/lambda to be able to catch the TypeLoadException when HugsLib isn't present
		try {
			((Action) (() => {
				var settings = HugsLibController.Instance.Settings.GetModSettings("TestModIdentifier");
				// add a mod name to display in the Mods Settings menu
				settings.EntryName = "Test Mod";
				// handle can't be saved as a SettingHandle<> type; otherwise the compiler generated closure class will throw a typeloadexception
				object handle = settings.GetHandle("testSetting", "Setting label", "Setting description", defaultValue);
				getSettingValue = () => (SettingHandle<bool>) handle;
			}))();
			return;
		} catch (TypeLoadException) {
		}
		getSettingValue = () => defaultValue;
	}
}
```

### HugsLib Events

Source: https://github.com/unlimitedhugs/rimworldhugslib/wiki/ModBase-Reference

Callbacks for various game states and events in RimWorld, allowing mods to hook into different stages of the game lifecycle. These include scene loading, world initialization, map events, game ticks, settings changes, and application shutdown.

```APIDOC
SceneLoaded:
  Called after a Unity scene change.
  Receives a `UnityEngine.SceneManagement.Scene` argument.
  Relevant scenes: `Entry` (menu), `Play` (game).
  Use `Verse.GenScene` to check the current scene.
  Note: Not all systems may be initialized.

WorldLoaded:
  Called after the game starts and the world is initialized.
  Maps may not be initialized yet.
  Useful for accessing `UtilityWorldObject`s.
  Not called on the 'select landing spot' world map.

MapComponentsInitializing:
  Called during map initialization, after `Verse.Map.ConstructComponents()`.
  Receives a `Verse.Map` argument.
  Good for accessing data before map loading is complete.
  Called before the map is populated from save data.

MapGenerated:
  Called after a new map finishes generating.
  Equivalent to overriding `MapComponent.MapGenerated` without needing a `MapComponent`.

MapLoaded:
  Called after map loading/generation is complete and `Verse.MapDrawer.RegenerateEverythingNow` executes.
  Receives a `Verse.Map` argument.
  Suitable for map-specific initialization.
  May be called multiple times if multiple maps are active.

MapDiscarded:
  Called after a map is abandoned or becomes inaccessible.
  Useful for cleaning up map-related data in `World` and `UtilityWorldObject`s.

Tick:
  Called every game tick.
  Receives the current tick number (`int`).
  Called even when on the world map, but not on the 'select landing spot' map.

SettingsChanged:
  Called after the Mod Settings dialog is closed.
  The changed setting may belong to another mod.

ApplicationQuit:
  Called before the game process shuts down.
  Useful for saving non-critical settings or custom data.
  Triggered by 'Quit to OS', window close button, Alt+F4.
  Not 100% reliable due to forced terminations or crashes.
  Modified settings are saved after this call.
```

### SettingHandle Properties

Source: https://github.com/unlimitedhugs/rimworldhugslib/wiki/Adding-Mod-Settings

Details the properties of the SettingHandle class, which control various aspects of how a setting is managed and displayed within the mod settings menu.

```APIDOC
SettingHandle:
  Name: string
    Description: The unique Id of the setting, specified as the first argument to ModSettingsPack.GetHandle. Must be unique to the mod that created it.

  Validator: function(string): bool
    Description: A method to validate player-assigned or XML-loaded values. Receives a string argument and returns a bool indicating validity. If validation fails on load, the default value is used. If validation fails when the player changes the setting, the change is rejected.
    Example: Settings.GetHandle("intSpinner", "title", "desc", 0, Validators.IntRangeValidator(0, 30));

  VisibilityPredicate: function(): bool
    Description: An optional method that returns true if the setting should be displayed in the menu. Useful for conditional visibility (e.g., Dev mode only).

  CustomDrawer: function(Rect): bool
    Description: A delegate to draw a custom control for editing the setting's value. Receives the screen area (Rect) for drawing and must return true if the value changed. Assign SettingHandle.Value when the setting changes.

  CustomDrawerFullWidth: function(Rect): bool
    Description: Similar to CustomDrawer, but takes over all drawing for the setting entry, including the title label and hover menu. The editing control occupies the right half of the Rect.

  CustomDrawerHeight: number
    Description: Specifies the height of the setting entry when using CustomDrawer or CustomDrawerFullWidth. Defaults to 32px.

  NeverVisible: bool
    Description: If true, the handle will never appear in the settings menu. Useful for hidden serialized data. Defaults to false.

  Unsaved: bool
    Description: If true, the handle's value will not be saved to the XML file. Useful for buttons or temporary settings. Defaults to false.

  CanBeReset: bool
    Description: If true, the handle will have a reset option in its context menu. Defaults to true.

  SpinnerIncrement: number
    Description: For int handles, specifies the increment/decrement value for the +/- buttons.
```

Explains how to disable the automatic creation of a Harmony instance and application of patches by overriding the HarmonyAutoPatch property.

```cs
public override bool HarmonyAutoPatch {
    get { return false; }
}
```

### Mod Settings - CanBeReset Property

Source: https://github.com/unlimitedhugs/rimworldhugslib/wiki/HugsLib-7.2-Update-Notes

The `CanBeReset` property for settings is now respected when resetting all settings for a mod. This allows developers to exclude specific settings from being reset.

```csharp
public class SettingHandle<T>
{
    // ... other fields
    public bool CanBeReset = true;
    // ...
}
```
